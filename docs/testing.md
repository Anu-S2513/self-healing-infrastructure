# Comprehensive Testing, Verification & Prometheus Query Guide

## 1. Important Prometheus Queries & Metrics

When presenting or diagnosing the Self-Healing Infrastructure, the following PromQL queries provide visibility into system state:

| Query Expression | Purpose & Operational Meaning | Expected Value When Healthy | Expected Value During Outage |
| :--- | :--- | :--- | :--- |
| `probe_success` | Boolean gauge from Blackbox Exporter indicating if the HTTP probe against NGINX succeeded with HTTP 2xx. | `1` (Healthy) | `0` (Outage detected) |
| `up` | Heartbeat gauge indicating whether Prometheus can successfully scrape its configured targets (`prometheus`, `blackbox`). | `1` for all targets | `1` (Scrapers still up, target fails inside probe) |
| `ALERTS` | Synthetic time series generated by Prometheus tracking all active alerts and their lifecycle state. | Empty or `alertstate="inactive"` | `alertname="NginxDown", alertstate="pending"` then `"firing"` |
| `probe_duration_seconds` | Latency in seconds taken to complete the synthetic HTTP probe. | `< 0.05` seconds (Typical: 5-15ms locally) | Drops or increases to probe timeout (5s) |
| `probe_http_status_code` | Raw HTTP response status code captured during the probe. | `200` | `0` (No HTTP response) |

## 2. The 11 Core Verification Tests

This project includes an end-to-end test suite covering every link in the self-healing chain.

### TEST 1: NGINX Website Availability
*   **Action:** Query `http://localhost:8081` via browser or PowerShell.
*   **Command:** `Invoke-WebRequest -Uri "http://localhost:8081" -UseBasicParsing`
*   **Expected Result:** HTTP `200 OK`, HTML containing "SELF-HEALING INFRASTRUCTURE" and "Status: Service Running".

### TEST 2: Blackbox Exporter Synthetic Probe
*   **Action:** Query Blackbox Exporter probe endpoint directly.
*   **Command:** `Invoke-WebRequest -Uri "http://localhost:9115/probe?target=http://nginx:80&module=http_2xx" -UseBasicParsing`
*   **Expected Result:** Metric `probe_success 1` and `probe_http_status_code 200`.

### TEST 3: Prometheus Target Scraping
*   **Action:** Inspect Prometheus targets endpoint.
*   **URL:** `http://localhost:9090/targets`
*   **Expected Result:** Jobs `prometheus` and `blackbox` both display state `UP` (green).

### TEST 4: Failure Injection (Stop NGINX)
*   **Action:** Stop the NGINX container.
*   **Command:** `docker stop self-healing-nginx`
*   **Expected Result:** Container state changes to `exited`. `probe_success` drops to `0`. `http://localhost:8081` connection is refused.

### TEST 5: Prometheus Alert Evaluation
*   **Action:** Monitor Prometheus Alerts dashboard at `http://localhost:9090/alerts`.
*   **Expected Result:** Alert `NginxDown` transitions from **Inactive** to **Pending** within 10 seconds, then to **Firing** after 30 seconds.

### TEST 6: Alertmanager Delivery
*   **Action:** Check Alertmanager API at `http://localhost:9093/api/v2/alerts`.
*   **Expected Result:** Alert `NginxDown` is registered with `state: active`, grouped, and delivered to the webhook receiver.

### TEST 7: FastAPI Webhook Handling
*   **Action:** Inspect FastAPI logs and recovery telemetry at `http://localhost:8000/recovery/status`.
*   **Expected Result:** `total_webhooks_received` increments, alert validated as firing `NginxDown`, cooldown verified, and Ansible remediation spawned.

### TEST 8: Ansible Playbook Execution
*   **Action:** Inspect Ansible playbook execution stdout in `self-healing-automation` logs.
*   **Expected Result:** Task `Inspect target container state` detects stopped container, task `Execute remediation - Start container` starts it, and task `Verify and assert that container is actively RUNNING` passes with return code 0.

### TEST 9: Docker Engine Container Recovery
*   **Action:** Check Docker container state.
*   **Command:** `docker inspect --format '{{.State.Status}}' self-healing-nginx`
*   **Expected Result:** Container state is restored to `running`.

### TEST 10: NGINX Website Restored
*   **Action:** Query `http://localhost:8081`.
*   **Command:** `Invoke-WebRequest -Uri "http://localhost:8081" -UseBasicParsing`
*   **Expected Result:** Returns HTTP `200 OK` with custom webpage intact.

### TEST 11: Prometheus Metric & Alert Resolution
*   **Action:** Check `probe_success` metric in Prometheus.
*   **Expected Result:** `probe_success` returns to `1`, alert `NginxDown` transitions back to **Inactive**, and Alertmanager sends a resolved webhook.
